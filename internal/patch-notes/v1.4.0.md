# v1.4.0 (2026-09-28)

A big one: a full redesign, a one-click icon download, a much sturdier
backend, and a fix for the "Owned tab is empty" report.

## What's new

- **New look.** The web app and the launcher share StarChart's design
  identity: amber on near-black, cut-corner shapes, League Gothic + Rajdhani.
  Fonts are bundled, so it still works fully offline. The header logo/favicon
  are local files now (they used to be loaded from warframe.com).
- **Launcher: Download icons.** One click fetches every item image once
  (~1,500 images, ~33 MB, progress bar, cancel/resume) and stores it locally,
  so the shop shows real art offline with no Warframe install needed.
- **Launcher: version in the header, logo, and an "updated, but your data
  isn't" notice** after an update (it appears from the *next* update onward -
  this is the first version that has it).
- **Market Sync pauses during missions**, like OpenTools Sync: no inventory
  sync or order handling mid-mission (a slow heartbeat only); it resyncs the
  moment the mission ends. Orders you place mid-mission wait until then - the
  shop tells you. The launcher shows "In mission (paused)".
- **Fixed: Owned tab empty.** The script asked for your inventory before the
  game had logged in; it now waits. The Owned tab also no longer gets stuck
  on an empty result until you reload.
- **Sturdier backend.** A malformed inventory snapshot can no longer crash the
  server, per-row lookups are ~5x faster, order input is validated, and
  finished orders no longer pile up in memory. See `BUGS.md`.

## Upgrading from v1.3.0 - please read

Updating the launcher does **not** update everything else. Three separate
steps:

1. **Launcher** - the installer/AppImage builds update themselves on startup
   (click **Update & Restart**). The portable Windows zip must be downloaded
   again.
2. **Server files** - the launcher does not bundle `server/`. In your
   OpenMarket folder run `git pull`, then **Stop** and **Launch** in the
   launcher. **Check for Issues** confirms the versions match.
3. **`Market Sync.pluto`** - delete the existing copy from your OpenWF
   `Scripts` folder and click **Install** in the launcher (Install never
   overwrites, so an old copy would silently stay). This is what carries the
   Owned-tab fix and the mission pause.

Your data is untouched, but new data is not downloaded automatically: click
**Update Data** in the shop for fresh prices, and **Download icons** in the
launcher if you want art stored locally.

## Known issues in this release

- **Not confirmed in-game:** the `Market Sync.pluto` changes (waiting for
  login, pausing during missions). They rest on a real server log and on
  OpenTools' confirmed mission check, but nobody has run this script through
  a mission yet. If something's off, `http://localhost:6155/script_log` will
  show "active mission detected" / "mission ended, resuming" and any errors.
  The mission check is untested in Railjack, Duviri and open-world zones.
- **The launcher UI was verified in a browser with a stubbed backend**, not in
  the packaged Tauri window; the new Rust command behind Download icons
  compiles but hasn't been exercised through Tauri.
- **Linux/Steam Deck is still unstable and unverified** (unchanged from
  v1.3.0 - see `BUGS.md`). Windows is the recommended platform.

---

- **Added `@wfcd/items` CDN as a second icon fallback tier, ahead of
  browse.wf** (local extraction → wfcd CDN → browse.wf → placeholder).
  99.6% coverage of this app's gameRefs against the actively-maintained
  `cdn.warframestat.us` CDN; live-verified via curl. No rebuild-breaking
  change — new `@wfcd/items` devDependency only feeds an offline
  generator script (`server/tools/generate-wfcd-icon-map.js` →
  `server/wfcd-icon-map.json`), not a runtime dependency. Needs a
  `server/` update (new files + `npm install`) to reach a running
  instance, no launcher rebuild. See DEVLOG.md for the full writeup.

- **Fixed: Owned tab empty until page reload / before login.** The script
  polled `inventory.php` before the game logged in (SNS 500 "missing
  accountId", every 5s) - it now waits quietly for login, and also checks
  the snapshot POST's HTTP status. The frontend no longer caches the
  owned map for the whole session (5s reuse, refetch after) and shows an
  "Inventory not received yet" hint when the server has no snapshot.
  Needs a `server/`-side update? No - only `public/app.js` and
  `scripts/Market Sync.pluto` changed; existing installs must delete and
  re-Install the script (Install never overwrites). No launcher rebuild.
  Script change unverified in-game. See BUGS.md / DEVLOG.md.

- **Backend hardening** (server-side only, no launcher rebuild): a
  malformed inventory snapshot can no longer crash the server (per-entry
  validation + every async route wrapped + a catch-all error handler);
  `getItems()` is memoized (per-row lookups ~70 ms -> ~15 ms; identical
  output); `POST /api/order` rejects Infinity/fractional/negative/string
  values; finished orders are pruned; an empty-inventory snapshot (`[]`)
  is accepted. Needs a `server/` update on existing installs (files:
  `itemsCache.ts`, `localIcons.ts`, `inventorySnapshot.ts`, `routes.ts`,
  `orderQueue.ts`, `index.ts`). Found by a local stress harness that is not
  part of this repo. See BUGS.md / DEVLOG.md.

- **Launcher: "updated, but data isn't" notice.** After the launcher
  updates itself, the Dashboard now shows a dismissible warning that
  updating the app doesn't download new data and the user still has to
  click Update Data in OpenMarket. Stays until dismissed; not shown on a
  fresh install. **Needs a launcher rebuild/release** to reach users
  (frontend-only change, `launcher/src/App.tsx` + `lib/config.ts`). See
  DEVLOG.md.

- **Launcher: version shown in the header** ("OpenMarket Launcher v1.3.0"), so a bug report can name the exact build. Same launcher-rebuild note as above; `launcher/src/App.tsx` + `App.css`.

- **Launcher: logo in the header**, left of the title (`launcher/src/assets/logo.png`, the 64px icon already generated for the app icon set). Same launcher-rebuild note as above.

- **Full redesign of the web app and the launcher** to StarChart's (OpenTools')
  design identity: amber on near-black, cut-corner shapes, League Gothic +
  Rajdhani. No behaviour change. Fonts are bundled locally (SIL OFL, licence
  notes in `public/fonts/` and `launcher/src/assets/fonts/`) and the two
  warframe.com hotlinks (logo, favicon) are now local files, so the app stays
  fully offline. README screenshots regenerated. Web app: `public/` update;
  launcher: **needs a rebuild/release**. See DEVLOG.md.

- **Launcher: "Download icons" button.** One click stores every item image
  locally (~1,500 images, ~33 MB, progress bar, cancel/resume) so the shop
  shows real art fully offline, no Warframe install needed. Server: new
  `downloadedIcons.ts` / `iconDownloader.ts`, `POST /api/download-icons[/cancel]`,
  `iconDownload` in `/api/status`. **Needs a `server/` update AND a launcher
  rebuild** (new Rust command `server_post`). See DEVLOG.md.
- **Market Sync.pluto pauses during missions** (inventory sync + order
  handling; slow heartbeat only), like OpenTools Sync. Orders placed
  mid-mission wait until it ends; the launcher shows "In mission (paused)".
  Existing installs must delete and re-Install the script. **Not tested
  in-game** - check `script_log` for the pause/resume lines. See DEVLOG.md.
